**Worker:** W2 · **Status:** done · **Date:** 2026-11-22

## What was delivered

- **`packages/core/src/tasks/subtasks.ts`** (new): the one-nesting-level
  subtask model over the S3-03 domain:
  - `canHaveSubtasks` (open standalone tasks only — SP depth invariant),
  - `attachSubtask` / `detachSubtask` (immutable link ops; illegal
    transitions throw `TaskDomainError` with codes `subtask-depth`,
    `subtask-attached`, `subtask-self`),
  - `subtaskProgress` (`{ total, done, pct }` in list order — the `2/5`
    badge S3-69 renders),
  - `aggregateSubtasks` / `withSubtaskAggregates` (parent's
    `timeSpentOnDay` merges own + children per day; `estimateMs` sums
    children into own — children-only estimates adopt the sum, all-null
    stays null; completion state deliberately NOT rolled up — SP keeps
    per-child doneness, the parent shows only the progress badge).
- **`packages/core/src/tasks/index.ts`**: re-exports the subtasks module
  (focus-lock house pattern — one entry for hosts).
- **`packages/core/tests/tasks-subtasks.test.ts`** (new): nesting rules
  (parentable matrix, depth/attach/self error codes), aggregation math
  (multi-day merge, estimate sums, null handling), progress counting in
  list order, and no-completion-rollup semantics.
