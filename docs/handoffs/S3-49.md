# S3-49 — Add-tasks-for-tomorrow + Today/Planner exclusivity

**Status:** done. **Worker:** W2. **Commit:** `983ad5b`.

## Core (packages/core/src/tasks/today.ts)

- **`tomorrowsTasks(tasks, today)`** — open tasks due exactly tomorrow
  (timed dues count by calendar day). The Today/Planner EXCLUSIVITY is
  structural: Today membership is due-day only (S3-65), so a tomorrow-due
  task can never appear in Today — and after the day rolls over it becomes
  today's with no sync step. One rule, both surfaces.
- **`planForTomorrow(tasks, ids, today)`** — due patches for the planning
  action; idempotent (already-tomorrow/done/won't-do produce nothing), so
  re-running the evening planning is a no-op. Callers persist each patch
  via PATCH /api/tasks/[id].

## UI (apps/web/src/components/tasks/PlanTomorrow.tsx)

Evening capture panel: short-syntax input (same grammar as the Today bar,
S3-09; `#tag`/`+project` created on submit) whose tasks land due TOMORROW
regardless of any `@due` typed — the panel's whole point; live title
preview (aria-live); tomorrow's planned list with tag names and a
per-row "Today" pull-back (PATCH due=today); calm empty state ("tomorrow
stays calm by default"). SSR-safe: `today` arrives as a prop (null until
the client clock mounts — the panel renders without the date until then).
