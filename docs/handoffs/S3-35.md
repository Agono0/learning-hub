# S3-35 — Configurable keyboard shortcuts

**Status:** done. **Worker:** W2. **Commit:** `fd5c3d9`.

## Core

`packages/core/src/tasks/shortcuts.ts` — the single resolver every surface
shares:

- **`DEFAULT_SHORTCUTS`** — the map mirroring what the tasks page ships
  (S3-73): `j`/`k` cursor, `x` select, `enter` open, `shift+enter`
  complete, `?` cheat sheet, `escape` cancel — each with a stable id and a
  `surface` (`task-list` | `global`).
- **Combo grammar**: lowercase final key + ordered modifiers
  (`ctrl→alt→shift`); `normalizeCombo` canonicalizes and rejects unknown
  modifiers/junk finals (null).
- **`effectiveShortcuts(overrides)`** — defaults with valid overrides
  applied (invalid ones fall back to the default).
- **`detectConflicts`** — combos claimed by 2+ bindings (the settings UI
  flags both rows).
- **`resolveShortcut(event, overrides)` / `comboFromEvent`** — event →
  binding id, including the `?`/`shift+/`/`shift+?` duality.

## Persistence

`apps/web/src/lib/shortcut-overrides.ts` — device-local
(localStorage `lh:shortcut-overrides`; keyboard bindings are per-device —
no `user_settings` column requested). zod-validated on every read;
`clearShortcutOverride` restores one default.

## UI

`apps/web/src/components/settings/ShortcutsSection.tsx` — the settings
section: per-row effective combo with a capture button (records the next
keypress; Escape cancels), per-row reset for overridden bindings, conflict
copy flagging both rows. Mounts in the Settings page's SP-config area
(X-01 noted this section was pending S3-35 — the mount is one line for the
settings-page owner to place alongside the other accordion sections).
