## What the workflow does (single `nightly` job on windows-latest)

Triggers: `schedule` cron `30 2 * * *` UTC + `workflow_dispatch` with a
`dry_run` boolean input (build + print the artifact list, no tag/release).
`permissions: contents: write`; concurrency group `nightly-<ref>` without
cancellation (a nightly must not be killed mid-release).

Steps, in order:

1. Checkout with `fetch-depth: 0` (history + tags needed for the prev-release diff).
2. Node 24 + npm ci + Rust toolchain + rust-cache + Next.js build cache — mirrors `native.yml`.
3. **Meta step** (bash): computes `VERSION = YYYYMMDD-<shortsha>` (UTC date + GITHUB_SHA),
   `TAG = nightly-<VERSION>` (exactly the O1-01/O1-07 tag contract), reads
   `minNativeVersion` from `apps/native/src-tauri/tauri.conf.json` (plain JSON, `node -p`),
   finds the previous nightly release via `gh release list --jq 'select(startswith("nightly-"))'`,
   downloads its `manifest.json` into `dist/prev/` (the "diff vs previous release"), and sets
   `requiresNative=true` when `git diff <prev-tag> HEAD -- apps/native packages/db` is
   non-empty (Rust/permissions changed → hot patch cannot ship it).
4. Builds `npm run web:tauri` (→ `apps/web/.next-tauri`) and `npm run app:build` (→ NSIS exe).
5. Resolves the installer file name; full-package URL becomes
   `https://github.com/<repo>/releases/download/<tag>/<installer>`.
6. **Generate manifest + patches**: invokes `scripts/update-manifest.mjs` with
   `--dir apps/web/.next-tauri`, channel nightly, the computed version/build-sha,
   `--requires-native`, `--full-package-url`, and `--prev dist/prev/manifest.json` when the
   previous release had one (patch set ≤ 5, newest-first).
7. **Pointer**: writes `dist/nightly/nightly.json` in the exact `updatePointerSchema` shape
   (channel, version, https manifestUrl on the release, publishedAt, notes).
8. **Signing**: `npx tauri signer sign` (minisign/Ed25519) over `manifest.json` and
   `nightly.json` using `TAURI_SIGNING_PRIVATE_KEY`/`..._PASSWORD` secrets (O1-09 ceremony).
   If the secret is absent the step warns and continues — the client REFUSES unsigned
   manifests by design, so an unsigned release is inert, never silently trusted.
9. **Dry run**: when `inputs.dry_run`, prints `ls -l dist/nightly` + manifest head and skips
   publishing (the "dry-run artifact list" acceptance).
10. **Release**: creates the tag + GitHub prerelease uploading manifest.json, nightly.json,
    their `.sig` files, all `patch-*.zip` bundles, and the Windows installer. Asset list is
    built defensively (missing sigs/zips are skipped, never hard-error).
11. Uploads `dist/nightly` as a workflow artifact on every run (even dry runs).
