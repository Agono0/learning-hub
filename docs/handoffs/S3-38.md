# S3-38 — Global search page upgrade: unified tasks + notes results

## Handler — `apps/web/src/server/handlers/search/route.ts`

`GET /api/search` now UNIFIES the SP task list into the same envelope: after
`searchAll` (FTS5/LIKE across the 17 knowledge surfaces), the handler runs
the core engine (`searchTasks` over `taskToSearchDoc`, S3-14) on the task
repo (`listTaskItems` from S3-15) and PREPENDS the hits — tasks are
actionable work, they lead. Contract per task hit:

- `kind: 'task'`, `id`, `title`, `snippet` (task notes), `href: '/tasks'`,
  and `done: boolean` (searching "did I already do X?" is a real query —
  done tasks are included and marked).
- Won't-do tasks are excluded twice over: the repo filter
  (`includeWontdo: false`) AND the core adapter (`taskToSearchDoc` returns
  null for them, S3-66).
- Cap: 8 task hits, so a task pile can't drown the knowledge surfaces.
- Ranking is the core engine's (title-prefix 100 > title-substring 80−
  offset > notes 40, recency tiebreak). FTS-indexed task search remains
  S3-67's job (FTS5 migration) — when that lands, the repo path here can
  switch to it without envelope changes.

## Faces of /api/search (single source of truth updated)

- `apps/web/src/lib/search-kinds.ts`: `SearchHitKind` gains `'task'`,
  `SEARCH_KIND_LABELS.task = 'Tasks'` — the ⌘K palette (CommandPalette)

- `apps/web/app/search/page.tsx`: KIND_LABELS entry, `done?: boolean` on
  the hit type, a "done" badge on completed task hits, subtitle + header
  copy mention tasks.

## Tests — `apps/web/tests/search-tasks-unified.test.ts`

the repo filter) rather than duplicated here.
