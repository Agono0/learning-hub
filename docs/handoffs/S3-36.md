# S3-36 — Markdown paste → tasks; task ↔ markdown checklist conversion

## Core — `packages/core/src/tasks/markdown.ts` (bfddedc)

- `markdownToTaskDrafts(markdown)` — total parser: checkbox items
  (`- [x]`, any bullet marker, ordered lists) AND bare lines become drafts;
  headings (`# …`) are document structure — skipped; fenced blocks
  (``` / ~~~) skipped whole; indentation (2 spaces / 1 tab per level)
  nests under the nearest shallower task with a frame-stack that carries
  each frame's TARGET array, so lines deeper than a subtask FLATTEN to
  siblings at level 2 (the task model's single nesting level, S3-04).
  Caps: 200 tasks (`MAX_PASTE_TASKS`), 200 subtasks per draft, 500-char
  titles (the task schema's own cap). `done` comes only from a checked
  checkbox. zod at the boundary (`markdownTaskDraftSchema`); junk in →
  `[]` out, never throws.
- `tasksToMarkdown(tasks)` — the inverse renderer (`- [x] title` +
  two-space-indented subtasks) with an exact round-trip guarantee
  (parse(render(tasks)) preserves titles, done state, one nesting level).
- `isMarkdownPaste(text)` — the UI gate: multi-line text or a single line
  starting with a list marker; a plain one-line sentence stays in the
  short-syntax input.

## UI — `AddTaskBar.tsx` onPaste (landed inside the concurrent 8b24d80 batch)

`onPaste` on the add-task input: `isMarkdownPaste` gates it (preventDefault
otherwise the normal input flow continues), `markdownToTaskDrafts` parses,
and each draft creates a task through the SAME short-syntax pipeline as
typed input (`#tag +project @due p1` in pasted lines behave identically —
`createFromLine` reuses parseShortSyntax + the ensureTag/ensureProject/
ensureRepeat resolvers). Subtasks nest via `parentId` (POST /api/tasks
accepts it from S3-16). Drafts always create OPEN tasks — a paste never
silently checks work off, even for `[x]` lines (the core keeps the flag;
the UI chooses the honest default). Partial failures surface as "Paste
created some tasks, then failed: …". Hint copy updated to mention paste.
