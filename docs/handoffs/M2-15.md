## What was built

- **Core invariant** `packages/core/src/focus-lock/emergency.ts`:
  - `SYSTEM_ALLOWED_APPS` — every known OEM dialer package + contacts +
    telecom router (AOSP, Google, Samsung, Xiaomi).
  - `mergeAllowlists(userApps)` — the session's EFFECTIVE allowlist is ALWAYS
    `user ∪ SYSTEM` (normalized, deduplicated). The system set can never be
    filtered out — not by settings, storage corruption, or a hostile sync;
    an empty user allowlist still yields the dialer set.
  - `sessionAllowlistSchema` — zod-validated persisted shape whose OUTPUT is
    the enforced list (what gets sent to Lock Task M2-11 / the Tier 2 watcher
    M2-12 / the Windows guard M2-09's allowlist param).
  - `EMERGENCY_DIALER_URI = 'tel:'` — the tile opens the DIALER, never a
    hardcoded regional number (911/112 stay regional; tested).
- **UI** `EmergencyDialerTile` — a ≥44px tile (`tel:` anchor) rendered in the
  focus page Max Focus area (the session surface the lock windows load);
  emerald accent, honest label "Emergency calls always available".
- **Platform notes**: Windows doesn't need an app allowlist for the dialer —
  the `tel:` flow is never swallowed by the M2-06 hook (only Win/Alt+Tab/
  Alt+F4/Ctrl+Esc are); Android enforcement flows through
  `mergeAllowlists` → Lock Task packages / watcher prefs, so the dialer
  package is always inside the pinned set.

## Test list (packages/core/tests/focus-lock-emergency.test.ts)

- empty user allowlist still yields the full system set;
- union + dedup + normalization (`.exe`/case/whitespace);
- hostile allowlist cannot remove system apps;
- `isAppAlwaysAllowed` across case/suffix forms;
- schema outputs the enforced list, defaults, JSON round-trip;
- dialer URI contract (tel:, no hardcoded digits).
