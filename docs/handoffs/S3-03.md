# Handoff — S3-03: Core task domain (model + ops)

**Worker:** W2 · **Status:** done · **Date:** 2026-11-22

## What was delivered

- **`packages/core/src/tasks/index.ts`** (new): the pure SP-parity task
  domain — zod schemas + types + immutable ops, no I/O (core rule):
  - `taskItemSchema` / `TaskItem` mirroring the S3-01 `task_items` table
    (one-level `parentId`, `timeSpentOnDay` date→ms map, `due`/`dueWithTime`,
    separate `deadline`, `wonthado`, `order`, `id: 0` = unpersisted draft).
  - `createTaskInputSchema` / `updateTaskInputSchema` (`create.partial()` —
    constraints still apply when a key is present) + `createTask`,
    `updateTask` (always bumps `updatedAt`, never mutates).
  - `completeTask` (idempotent; throws `TaskDomainError('wontdo-cannot-complete')`
    on a won't-do task), `reopenTask` (clears done AND won't-do),
    `duplicateTask` (SP `(copy)` semantics: fresh id, open, empty time map,
    order +1, schedule/tags/priority survive; overrides accepted).
  - `bulkOpSchema` / `bulkApply` — the ONE batch path (complete/reopen/
    wontdo/setPriority/setProject/addTags/removeTags) returning
    `{ applied, skipped }`; per-task failures land in `skipped` with a
    human reason and never abort the batch (handlers S3-16 persist the
    applied rows transactionally).
  - `validateTask` — habits-style `{ ok, errors, warnings }`: timed-vs-date
    due format rules, positive estimate, no self-parenting, doneAt
    consistency, deadline-before-due and done+wontdo advisories.
- **`packages/core/src/tasks.ts`** (new): thin `@learning-hub/core/tasks`
  subpath entry (focus-lock pattern).
- **`packages/core/src/index.ts`**: barrel line `export * from './tasks'`.
- **`packages/core/tests/tasks.test.ts`** (new): 20 SP-parity cases — create
  defaults/bounds, immutable patches, complete/reopen transitions incl. the
  won't-do guard + error code, duplicate semantics (open copy of a done
  task), bulk apply with skips/dedup/idempotent complete, and the full
  validation matrix.
