# Handoff — S3-07: Core repeat engine

**Worker:** W2 · **Status:** done · **Date:** 2026-11-22

## What was delivered

- **`packages/core/src/tasks/repeat.ts`** (new): the SP-parity recurring
  engine, pure date math (`YYYY-MM-DD` in/out, no clock reads):
  - `repeatCfgSchema`/`RepeatCfg` mirroring `task_repeat_cfgs` (cycle
    `d|w|m|y`, interval 1–999, inclusive `endDate`, deduped+sorted
    `skipDates`, `reAnchor` mode) + `createRepeatCfg` (normalizes skips),
  - `addCycle` with SP clamping: Jan 31 + 1 month = Feb 28 (un-clamps on
    31-day months), Feb 29 + 1 year = Feb 28 in common years and survives
    leap years,
  - `nextDueAfter(cfg, anchor, interactionDate?)` with the three re-anchor
    modes: `scheduled` (ignores completions), `completion` (anchors from the
    completed day — "every 3 days from when you did it"), `postponed`
    (anchors from the postponement day); falls back to the schedule anchor
    when no interaction is given; null past `endDate` (a skip roll past the
    end also kills the repeat — SP parity),
  - `rollPastSkips` semantics inside the above: occurrences never surface
    on skipped days (bounded roll, 366 steps),
  - `projectOccurrences(cfg, startAfter, count)` for S3-26/S3-25 previews,
  - `isOccurrenceOn(cfg, day)` interval-aligned matcher (skip-rolled days
    surface on the free day) for S3-49's Today sync,
  - `validateRepeatCfg` (end-before-start blocker; out-of-window and
    > 50%-skipped-window advisories).
- **`packages/core/src/tasks/index.ts`**: re-exports the module.
- **`packages/core/tests/tasks-repeat.test.ts`** (new): 20+ SP-parity cases —
  clamping matrix, daily/weekly/monthly cadences, scheduled-vs-completion-vs-
  postponed anchors, single/multi skip rolls, endDate cutoffs (plain + rolled),
  projections with skips, occurrence matcher, cfg validation + zod bounds.
