## What was built

- **Trigger**: when the O1-27 progress reading shows the download fully
  arrived (`isDownloadComplete`: downloaded ≥ total > 0) while `applying`,
  the banner fires the OS notification EXACTLY ONCE (ref-guarded, re-armed
  when the applying phase ends — a re-download notifies again).
- **Delivery through the shared gate**: `notifyUpdateReady()` uses
  `@/platform/permissions` (`requestPermission('notifications')` +
  `deliverLocalNotification` — Tauri plugin or Web Notifications). Permission
  is REQUESTED at completion time, never assumed; denied/unsupported → false
  and the in-app banner remains the always-present surface (the OS
  notification is a bonus, not the contract). Copy: "Update ready / Restart
  Learning HUB to apply the update — nothing changes until you do."
- Ask-first preserved: the notification announces readiness; nothing applies
  until the user restarts (the banner's download consent was the only gate).
