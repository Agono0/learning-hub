## What was built

- **Core gate** `shouldAutoUnlockBattery(levelPct, pluggedIn, thresholdPct = 15)`:
  true exactly when NOT plugged in AND level ≤ threshold. Total/defensive —
  NaN/out-of-range/non-finite readings or thresholds return `false` (a broken
  sensor can never end a session). Charging devices never unlock early; the
  hard cap remains `advanceSession`'s `hardCapAtMs` → reason `timer` (M2-01).
- **Integration contract**: when the gate fires, callers invoke
  `forceUnlockSession(session, clock, 'battery')` (M2-01) — ends the session
  with the logged reason (tested end-to-end in the battery test file).
- **Android monitor** (wired): `batteryStatus` Kotlin command reads the sticky
  `ACTION_BATTERY_CHANGED` broadcast (no permission), exposes
  `focus_android_battery_status` in lib.rs → `{ levelPct, pluggedIn }`.
- **Windows monitor**: `GetSystemPowerStatus` needs the `Win32_System_Power`
  crate feature — LEAD-only Cargo.toml, request filed in
  `docs/SHARED_CHANGES.md` (same pattern as M2-08's registry feature). Until
  applied, the Windows native reading is the only missing piece; the DECISION
  logic + tests here are complete and platform-independent.
