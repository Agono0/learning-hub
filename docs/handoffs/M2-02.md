# M2-02 handoff — PIN vault (PBKDF2 + security-question recovery)

Worker: W3 · Branch: `feature/mega-run` · Files: `packages/core/src/focus-lock/pin.ts` (new),
`packages/core/tests/focus-lock-pin.test.ts` (new). Dep: M2-01.

## What was built

`@learning-hub/core/focus-lock/pin` (import via subpath; the one-line
`export * from './pin'` in `focus-lock/index.ts` is deferred — W1's O1-06 is
in-flight on that area; the subpath import works today through the package
exports map):

- **`createPinVault({ pin, question?, answer? }, { iterations? })`** →
  `PinVault` record: PBKDF2-HMAC-SHA256, fresh 16-byte CSPRNG salt per record,
  hex-encoded fields (no base64 ambiguity), zod-validated at every boundary.
  Question/answer must be provided together; the answer is normalized
  (trim + lowercase) then hashed under its OWN salt — it never appears in the
  clear and never re-uses the PIN's salt.
- **`verifyPin(vault, pin)`** → boolean; malformed guesses return `false`
  (never throw); tampered/corrupted records fail closed (schema validation
  rejects before deriving).
- **`verifySecurityAnswer(vault, answer)`** → boolean; same normalization as
  creation; `false` when no question configured.
- **`constantTimeEqual(a, b)`** — exported, XOR-accumulate compare (no
  content-dependent short-circuit).
- **`pinVaultSchema` / `PinVault`** — the record to embed in userSettings JSON
  (`version: 1, iterations, salt, hash, question?, answerHash?, answerSalt?`).
  Validate on every read; a corrupted record means "no vault", not a crash.
- **`pinSchema`** — 4–12 digits (typed under pressure, resists brute force via
  600k iterations + handler-side rate limiting, M2-04).
- **`PIN_PBKDF2_ITERATIONS = 600_000`** (OWASP 2023+ for SHA-256, chosen
  deliberately above sync-crypto's 210k envelope default because a numeric PIN
  is low-entropy).

Web Crypto only (`crypto.subtle`, `crypto.getRandomValues`) — zero
dependencies, no node builtins, runs in Node 22+, browsers, WebView2 and the
Android webview worker.

## Test list (packages/core/tests/focus-lock-pin.test.ts)

- pinSchema accept/reject matrix (length, digits-only, whitespace).
- create: schema-valid record, iteration default/override, per-record salt
  uniqueness, question/answer togetherness, answer hashed (never plaintext),
  boundary rejects.
- verifyPin: right/wrong, malformed guesses → false, corrupted record fails
  closed (bit-flipped hash, bad salt, negative iterations).
- verifySecurityAnswer: normalization, no-question vault → false, empty →
  false, JSON round-trip (persisted record still verifies).
- constantTimeEqual: equal/unequal/length-mismatch/empty/large-buffer.
