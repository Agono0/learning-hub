## What was built

- **`persistedMaxFocusSessionSchema`** — the device-local record the web layer
  saves at Max Focus session start (machine fields from M2-01 + the ENFORCED
  allowlist from M2-15 + `resumeExpected: true` — only true records resume;
  ended sessions never do).
- **`resumeMaxFocusSession(persisted, clock)`** — the boot/kill decision:
  - window over (planned end or hard cap passed while off) → `null`
    (session complete — the M2-34 report card takes over);
  - corrupt persistence (wrong cap order, bad shape, `resumeExpected: false`,
    null) → `null` — FAIL CLOSED, never a wrong lock;
  - still inside the window → a fresh M2-01 machine session preserving the
    original wall deadlines EXACTLY (no locked time lost) with the monotonic
    anchor RE-BASED to now.
- **The fresh-anchor rule** (the subtle part, documented in the header): after
  a reboot the monotonic clock restarted, so carrying the old
  `monoAnchorMs` would trip the tamper gate (M2-20) instantly and falsely.
  Re-basing is the honest contract: PRE-boot wall-clock manipulation is
  undetectable by monotonic means (docs/LIMITATIONS.md), POST-resume
  manipulation still is — tested (first advance passes, later wall tamper
  would trip).

## Native pieces already in place (M2-14/M2-23)

`MaxFocusBootReceiver` relaunches the app on BOOT_COMPLETED (owner exemption);
the web layer's boot flow then: `loadPersistedSession` (localStorage, device
pattern) → `resumeMaxFocusSession` → non-null ⇒ `invoke('focus_session_apply',
snapshot)` + re-arm Lock Task (M2-11) / watcher state (M2-12) ⇒ the machine
continues via `advanceSession`.

## Test list (packages/core/tests/focus-lock-resume.test.ts)

- resume inside the window: deadlines preserved, fresh anchor, tamper gate
  passes on the first post-resume advance;
- planned end passed → null; hard cap passed → null;
- fail-closed on corrupt records (cap order, empty id, resumeExpected false,
  null);
- a resumed session still enforces its ORIGINAL planned end (reason `timer`);
- JSON round-trip (device-local storage path);
- equivalence with a fresh `startMaxFocusSession` of the same shape.
