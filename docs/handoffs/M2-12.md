## What was built

- **Kotlin `MaxFocusAccessibilityService`** (Tier 2, non-owner fallback):
  watches `TYPE_WINDOW_STATE_CHANGED` only; when a session is armed and the
  foreground package is not allowlisted, brings Learning HUB back in front
  (`FLAG_ACTIVITY_NEW_TASK | REORDER_TO_FRONT`). State = SharedPreferences
  (`active` + allowlisted packages) written per-session by the plugin — the
  service is structurally inert between sessions.
- **PRIVACY LAW (structural, not behavioral):** the service config sets
  `canRetrieveWindowContent="false"` — screen content is impossible to read,
  not merely unused. Disclosed verbatim in three aligned places: the service
  header, the system settings description string
  (`max_focus_strings.xml`), and the web disclosure screen.
- **Plugin additions** (`MaxFocusAndroidPlugin`): `setWatchState { active,
  packages }` (arm/disarm per session) and `openAccessibilitySettings`
  (deep-link to the grant screen — the disclosure shows BEFORE it).
- **Rust bridge**: `focus_android_set_watch_state` +
  `focus_android_open_accessibility_settings` (desktop → "Android-only").
- **Web**: `platform/accessibility-watcher.ts` wrapper (null/no-op
  off-Android, failures never throw) and `MaxFocusDisclosures.tsx` — the
  accessibility disclosure (what it does / what it can NEVER read / when it
  acts / how to revoke) + the settings jump button; structured for M2-17 to
  add the Device Admin screen and M2-16 to compose into the checklist.
