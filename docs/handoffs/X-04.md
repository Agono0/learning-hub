# X-04 — Embodied Learning & Gesture Studio

**Status:** shipped
**Branch:** feat/embodied-learning-studio

## What landed

- Core engine (`packages/core/src/embodied-learning/engine.ts`): gesture plan
  evaluation, gesture-speech mismatch analysis, concreteness-fading ladder
  validation, enactment session scoring, studio phase flow.
- Content library (`content.ts`): six canonical scenarios with full gesture
  plans, fading ladders, tracing exercises, enactment tasks, reflection
  prompts and citations.
- Tests (`packages/core/tests/embodied-learning.test.ts`).
- Web: runtime-neutral handler at `/api/embodied-learning`, page at
  `/embodied-learning`, `EmbodiedLearningStudio` component (six tabs).
- MCP: six `embodied_*` tools. CLI: `embodied-learning` command with six
  subcommands. Server: six `/cognitive/embodied/*` routes.
- Docs: `docs/embodied-learning.md`, learning-science entry.

## Notes for the next agent

- The studio is stateless by design; all hosts call the same pure engine.
- Web workspace typecheck is CI-gated (too heavy for local sandboxes); core,
  mcp, cli and server typechecks were green locally at ship time.
- New scenarios go in `CANONICAL_EMBODIED_SCENARIOS`; the test suite
  schema-validates every entry and checks each ladder with
  `validateFadingLadder`.
