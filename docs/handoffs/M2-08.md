## Closeout completion (2026-11-22, W1)

The row was partially landed: docs/max-focus.md documented the tier and
`lock_win.rs` comments referenced it, but the implementation was missing.
**Built now** (CI compiles; local cargo runs are forbidden by rule 17):

- **`apps/native/src-tauri/src/lock_watchdog.rs`** (new): the real M2-08 —
  `DisableTaskMgr` DWORD write under
  `HKCU\Software\Microsoft\Windows\CurrentVersion\Policies\System` via
  self-contained advapi32 externs (no Cargo feature — the `idle.rs`
  pattern), the re-assert watchdog thread (2s interval, atomic flag), the
  `TaskMgrGuard` whose **Drop restores the policy unconditionally** (the
  M2-08 restore guarantee is structural, not convention), and the
  session-lifetime slot API (`acquire_hardening`/`release_hardening`,
  idempotent both ways). 2 unit tests.
- **`lock_win.rs`**: `apply_lock_windows_with_allowlist_and_tier` (the
  original signature preserved as a tier-1 wrapper) + the release path
  drops the hardening.
- **`focus.rs`**: `MaxSessionSnapshot.tier` (serde-default `Option<String>`
  — older session files stay readable) and the apply call site passes
  `tier == "windows-admin"`. Two test literals updated.

Design decision recorded: the watchdog is a **thread in this process**,
not a separate executable — the Drop-guard restore covers everything a
second process would, without a binary to sign or a child to clean up.
