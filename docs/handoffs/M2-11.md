## What was built

- **Kotlin `MaxFocusLockTask`** (registered alongside `MaxFocusAndroidPlugin`
  in the same `max-focus-android` plugin family):
  - `startLockTask { packages }` — Device-Owner-gated:
    `setLockTaskPackages(adminComponent, packages)` + `activity.startLockTask()`.
    Rejects non-owner devices WITH the Tier-2 fallback pointer (M2-12) and
    rejects empty allowlists (the emergency dialer must always be present, M2-15).
  - `stopLockTask` — idempotent (`IllegalStateException` swallowed: not pinned).
  - `lockTaskStatus` — `{ packageName, isDeviceOwner, isLockTaskPermitted, packages? }`.
- **Rust bridge**: `focus_android_start_lock_task(packages)` +
  `focus_android_stop_lock_task` (desktop answers "Android-only"; registration
  unconditional so `generate_handler!` compiles everywhere).
- **Web**: `platform/lock-task.ts` — `lockTaskSupported()`, `startLockTask(packages)`
  (null + Tier-2 fallback on non-owner/failure; empty-allowlist guard before any
  native call), `stopLockTask()` (idempotent).

## Contract for downstream

- M2-16/M2-25 UI + M2-23 Rust session commands: the session's allowlisted
  PACKAGES (`FocusLockPayload.apps`, package-normalized) flow into
  `startLockTask`; the emergency dialer package must always be in the list
  (M2-15 validates on the web side).
- M2-12 (Tier 2) is the fallback for non-owner devices — when
  `startLockTask` resolves `null`, the UI routes there.
- M2-24 (reboot resume): re-issue `startLockTask` on boot for an active
  session; Android itself ends lock task if the owner app is killed, and the
  persisted session state re-pins.
