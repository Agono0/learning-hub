# S3-30 — Metrics page: per-day records, aggregates, hand-rolled SVG charts, heatmap

(+ covers **S3-89**'s activity heatmap data builder — `buildActivityHeatmap`
lives in the same pure module; S3-89's unit tests are
`packages/core/tests/metrics.test.ts`.)

## Core — `packages/core/src/metrics.ts` (new, exported from the index)

One record shape `{ day: 'YYYY-MM-DD', value }` covers every daily series:

- `metricDaysFromSessions(rows)` — folds the S3-18 session-log shape
  (`{day, sessionMs}`) into sorted per-day records.
- `aggregateMetricDays(days)` — total, activeDays, avgPerActiveDay, maxDay,
  `currentStreak` / `longestStreak` walking CALENDAR days (sparse series
  stay honest; gaps break runs).
- `buildLinePoints(days, {width,height,padX,padY})` — viewBox-space
  coordinates for the hand-rolled SVG polyline (index-spread x, value-scaled
  y, baseline at the bottom; all-zero series sit on the baseline; single
  point guard). No chart lib, analytics-page pattern.
- `buildActivityHeatmap(days, weeks, today)` (S3-89) — GitHub-style grid:
  Monday-aligned columns, `weeks` window ending at `today`'s week (today
  included, NO future cells), levels = quartiles of the window max
  (`0..HEATMAP_LEVELS=4`), junk days skipped. Total, never throws.

## Page — `apps/web/app/metrics/page.tsx`

Two series sections over REAL landed data (S3-19's metrics handler can feed
more series later — the record shape already fits):

- **Tracked time**: `GET /api/tasks-time?from&to` (S3-18) → per-day ms →
  aggregate stat row (total / active days / avg / best day), 30-day SVG
  line chart, 12-week heatmap, streak line. Honest empty state.
- **Reviews**: `GET /api/analytics`'s `heatmap` payload (core
  `heatmapData`, reused not duplicated) → same aggregate + line + heatmap
  treatment.

SVG uses `var(--hub-border)` / `var(--ac-soft)` / `var(--ac-strong)` tokens
(calm indigo ramp — no reds), `.scroll-x` on wide charts (mobile-first),
`<title>` tooltips per cell. SSR-safe: ranges/today/tz are effect-set —
`renderToString` renders the pending shell + empty-state copy, and the
integration test asserts no `Date.toISOString` at render.
