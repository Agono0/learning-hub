## What was built

- **`focus_session_apply(snapshot)`**: applies the lock windows scoped to the
  session's allowlisted apps (`apply_lock_windows_with_allowlist` — keyboard
  hook + refocus guard ride along, M2-06/07/09), stores the
  `MaxSessionSnapshot` in memory, emits **`max-focus://applied`** with the
  snapshot. The snapshot mirrors the M2-01 `MaxFocusSession` field-for-field;
  the STATE MACHINE stays in the web layer (core TS) — Rust is the actuator.
- **`focus_session_status`**: `{ locked, keyboardHookActive, refocusGuardActive,
session }` — guard fields are cfg-gated (false off-Windows); feeds M2-25's
  session history UI and M2-30's e2e smoke.
- **`focus_session_release(reason)`**: validates the reason against the M2-01
  union (`timer|pin|battery|failure|tamper` — friction logs can never record
  junk), releases windows + guards, clears the snapshot, emits
  **`max-focus://released { reason, sessionId }`** — the event the early-exit
  flow (M2-18) and post-session report card (M2-34) listen for.
- Pure/testable pieces: `is_session_unlock_reason` + snapshot serde round-trip
  (`#[cfg(test)] max_session_tests` — CI cargo test).

## Persistence boundary

The snapshot is in-memory ONLY; durable persistence (reboot/kill resume) is
M2-24, which will move the snapshot behind the device-local store + reconcile
on boot (the release/apply event names and payload shapes here are its API).
