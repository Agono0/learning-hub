## S3-44 — per-view customizer

- `apps/web/src/lib/task-view-settings.ts` — the row-presentation state per
  view: show/hide toggles (estimate, priority, deadline, tags, project) +
  sort (`manual|due|deadline|priority|estimate|title`) + group
  (`none|project|tag|priority|due`). Zod-validated on every read; corrupted
  localStorage degrades to defaults. Device-local by design (audit L7a
  family): `task_views` rows own the shareable half (name/kind/filter/
  sort/group), these toggles stay on the device.
- `apps/web/src/components/tasks/TaskViewCustomizer.tsx` — the controlled
  panel: five show/hide `Toggle`s, sort/group `SelectField`s, and the
  "Save as view" flow (opens on demand — one primary action per state,
  confirm-in-place). `onSaveView(name, settings, filter)` is the parent's
  persistence hook; the default wiring is a POST to /api/tasks-views.
- **No `core/boards.ts` edits** (lane brief) — the panel composes W3's
  rule-chip types via the plain `filter` record.

## S3-85 — save-as-view from any filtered list

`apps/web/src/components/tasks/SaveViewBar.tsx` — list-agnostic capture:
props are `{ filter, sortBy, groupBy, onSaved }`; saving POSTs
`{ name, kind: 'custom', filter, sortBy, groupBy }` to /api/tasks-views
(S3-17's persisted rows) via the transport (raw-fetch ban holds), shows a
react-query error inline, and confirms in place ("Saved 'name'" + Save
another). The boards page and the Today/Inbox list can mount it with their
current state; page wiring was deliberately left to the page owners (W3
boards / W1 tasks page) to avoid cross-lane edits — mounting is a one-liner
documented here.
