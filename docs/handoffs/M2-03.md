# M2-03 — Max Focus lock-state persistence (repo layer)

**Status:** done. **Branch:** `feature/mega-run`. **Worker:** W2.

## Lead decision applied

The original `[!]` (new `max_focus_sessions` table) was resolved by the lead:
**reuse the extended `focus_sessions` table**. Migration `033-max-focus-sessions.ts`
(lead-applied) added `state`, `tier`, `exit_reason`, `hard_cap_at`; `schema.ts`
mirrors them (`packages/db/src/schema.ts`, fields commented `M2-03`).

## What this change adds

All in `packages/db/src/repos/focus-lock.ts` (re-exported via
`packages/db/src/repos/index.ts` → `@learning-hub/db`):

- **Lifecycle stamps** — the existing mutators now keep the new columns in step:
  - `startMaxFocusSession(input)` — input widened with `tier?: FocusSessionTier`;
    inserts `state: 'locked'`, `hardCapAt = start + MAX_FOCUS_HARD_CAP_MINUTES (240)`,
    `tier` (null until the native bridge reports it). Returned lock status carries
    `state`/`tier`/`hardCapAt` too.
  - `requestMaxFocusEarlyExit` → `state: 'cooldown'`;
    `cancelMaxFocusEarlyExit` → back to `state: 'locked'`;
    `confirmMaxFocusEarlyExit` → `state: 'ended'` + `exitReason: 'pin'`.
  - `closeExpiredMaxSession` — now ends at the **earlier** of `lockedUntil` and
    `hardCapAt` and stamps `state: 'ended'`, `exitReason: 'timer'`.
- **Setters/getters** for the platform-driven paths (Rust/Kotlin bridges):
  - `getMaxFocusSessionRow(id, dbOrTx?)`
  - `setMaxFocusSessionState(id, phase, dbOrTx?)` (throws on unknown id)
  - `setMaxFocusSessionTier(id, tier | null, dbOrTx?)`
  - `setMaxFocusSessionWindow(id, { lockedUntil?, hardCapAt? }, dbOrTx?)`
  - `endMaxFocusSessionByReason(id, { reason, endedAt?, actualMinutes?, completed? }, db?)`
    — battery (M2-19) / tamper (M2-20) / failure (M2-23) / natural timer ends;
    idempotent, first end wins, no XP (rule 7 stays on the canonical path).
  - `extendMaxFocusSession(extraMinutes, db?)` — planned end += extra, clamped to
    the hard cap; refused while an exit is pending (reflection gate cannot be outrun).
  - `toMaxFocusMachineSession(row, monoAnchorMs)` — maps a row onto the core
    `MaxFocusSession` so callers can run `advanceSession` / `requestSessionExit` /
    `confirmSessionExit` over real data. The monotonic anchor is a call parameter
    (never persisted — meaningless across boots/devices, per `core/focus-lock/resume.ts`).
    Phase derivation prefers raw facts (`endedAt`, `exitRequestedAt`) over the cached
    `state` column so a stale cache cannot resurrect an ended lock.
- **History** — `listMaxFocusSessions({ limit })`, `listMaxFocusExits({ limit })`
  for M2-25 / the GET history handler.

## Core additions (additive)

- `focusExitActionSchema` confirm variant — optional `pin` + `vault` (M2-04 handler
  requires both; older callers still parse).
