## What was built

- **Kotlin `MaxUpdatePlugin`** (`@TauriPlugin`, mirrors the haptics plugin
  pattern verified against tauri 2.12.5 sources): `deviceInfo` (primary ABI,
  SDK level, consent state) and `installApk` (stream APK into a
  `MODE_FULL_INSTALL` PackageInstaller session, commit with an intent back
  into `MainActivity`, FLAG_MUTABLE on API 31+ for status extras).
  **Consent is enforced at every stage**: missing
  `canRequestPackageInstalls()` → opens `ACTION_MANAGE_UNKNOWN_APP_SOURCES`
  for THIS package and resolves `{ consentRequired: true }`; the system
  installer dialog is the final consent stage. No silent path exists.
- **Manifest**: `REQUEST_INSTALL_PACKAGES` (consent gate for the per-app grant
  screen — documented as never-silent).
- **Rust bridge** (`lib.rs`): `max_update_plugin()` registers
  `dev.learninghub.app/MaxUpdatePlugin` via `PluginApi::register_android_plugin`
  (android-cfg'd; desktop compiles the commands with a clean "Android-only"
  error) and manages the `PluginHandle`; commands
  `update_android_device_info` + `update_install_android_apk` are registered
  unconditionally in `generate_handler!`.
- **Webview wrapper** `platform/sideload.ts`: `sideloadSupported()`,
  `androidDeviceInfo()`, `installSideloadApk(apkPath)` — dynamic tauri API
  import behind `isTauri` (haptics.ts pattern), null on web/failure.

## CI verification (rule 17 — no local compile)

Kotlin compiles in the native.yml Android matrix (gen/ is tracked git);
Rust compiles in the same job + desktop check. Patterns were matched against
the LOCAL cargo registry sources (tauri 2.12.5 `register_android_plugin`,
`Invoke`, `JSObject`, `Builder.setup` signatures) — reading, never building.
