## What was built

- **`write_session_file` / `read_session_file` / `clear_session_file`** — the
  MaxSessionSnapshot persisted to `<app_data>/max-focus-session.json`,
  atomically (tmp + rename, same-directory — never a torn file), parse errors
  and missing files fail CLOSED (None), never a wrong lock.
- **Lifecycle wiring**: `focus_session_apply` persists the snapshot; on app
  RESTART (no reboot needed — no BOOT_COMPLETED involved) the FIRST
  `focus_session_status` call transparently re-populates the in-memory
  snapshot from disk (`restore_persisted_max_session`), so the UI/M2-25/M2-30
  never see "unlocked" after a restart. `focus_session_release` clears the
  file.
- **Division of labor**: the native layer restores the STATE (truth for
  status); the WEB layer's M2-24 resume decision decides whether the lock
  re-applies (calls `focus_session_apply` again after
  `resumeMaxFocusSession`). Reboot resume = M2-14's receiver + M2-24 web flow;
  app-restart resume = this task.
