## What was delivered

- **`apps/web/src/lib/updates.ts`** (new): the client-side update service.
  - `resolveUpdateState(raw)` — pure, total flag reader: `play` (case- and
    whitespace-insensitive) → `{ flavor: 'play', selfUpdateEnabled: false }`;
    `nightly | beta | stable` → self-update on; unset/empty/unknown → fallback
    `nightly` + self-update **on** (sideload/dev default). The restrictive
    value must be spelled exactly so a typo can never silently flip the store
    gate either direction.
  - `UPDATE_BUILD_FLAVOR` / `SELF_UPDATE_ENABLED` — module-level constants
    resolved once at import time from the build-time-inlined
    `process.env.LH_UPDATE_CHANNEL`. O1-14 (Settings > Updates) and O1-15
    (banner) gate every update action on `SELF_UPDATE_ENABLED`.
  - Types (`UpdateBuildFlavor`, `UpdateBuildState`) and `UPDATE_CHANNEL_ENV`
    exported for downstream tasks; channel validation reuses W3's
    `updateChannelSchema` from `@learning-hub/core/update`.
- **`apps/web/next.config.ts`**: added `LH_UPDATE_CHANNEL` to the `env` map so
  the CI-set value is inlined into every bundle (web dev, static `.next-tauri`
  export, webview worker). Unset at build time → `''` → `nightly` default.
- **`apps/web/tests/update-channel-flag.test.ts`** (new): both-ways unit tests —
  pure reader matrix (play/channel/unset/unknown/junk) plus import-time
  module-constant tests using `vi.stubEnv` + `vi.resetModules` (same code path
  the Next build inlines).
