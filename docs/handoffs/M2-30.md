# M2-30 — Desktop e2e smoke: lock apply→release round-trip

`tests/e2e/max-focus-lock-roundtrip.test.ts` (vitest e2e, pure node — no
Tauri runtime, no DB).

## What it covers (the round-trip CONTRACT)

A headless vitest run cannot create real lock windows — that needs the Tauri
runtime and is covered by the cargo tests in `focus.rs` plus the CI native
job. This smoke therefore pins the full contract the three layers implement
together, end to end:

1. **Apply** — `startMaxFocusSession` (M2-01 machine) → the native snapshot
   wire format `focus_session_apply` deserializes: key-for-key assertion of
   the serde field names of `MaxSessionSnapshot` (`session_id`,
   `started_at_ms`, `planned_end_ms`, `hard_cap_at_ms`, `mono_anchor_ms`,
   `allowed_apps`). Drift between web and Rust breaks the build/test here
   first.
2. **Persist** — atomic tmp+rename file semantics mirroring focus.rs
   `write_session_file`; corrupt/missing reads fail CLOSED (null), never a
   wrong lock.
3. **Status** — `advanceSession` mid-window stays `locked` with no events;
   the session object still parses through `maxFocusSessionSchema` (M2-03
   row shape).
4. **Release** — natural end (reason `timer`, file cleared); PIN exit flow
   with the non-bypassable 60 s reflection (confirm-during-cooldown no-op,
   wrong-PIN no-op, then `pin`); force paths (`battery`/`failure`/`tamper`).
5. **Re-apply + resume** — a fresh session locks again (round-trip), and the
   M2-24 persisted-record path (`resumeMaxFocusSession`) rebuilds a locked
   session with preserved deadlines + fresh monotonic anchor, then releases.

## Platform guard (per brief)

The desktop lock applies on Windows only (M2-05…M2-07), so the four
round-trip tests are `it.skipIf(!ON_WINDOWS)` — on Windows CI they run
fully; on Linux/macOS CI they report as skipped (graceful, documented in the
test header). One describe runs on EVERY OS: the unlock-reason union parity
between core and the Rust gate `is_session_unlock_reason`
(`RUST_UNLOCK_REASONS` typed as the core union + a compile-time
`Record<SessionUnlockReason, true>` exhaustiveness guard — if core ever adds
a reason, CI fails until the Rust mirror grows too). No new core exports
were needed (W2 owns focus-lock in-flight).
