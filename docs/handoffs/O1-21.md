## What was built

- **`scripts/generate-apk-delta.mjs`**: wraps the `bsdiff` CLI
  (`--bsdiff-bin` override for tests) to produce
  `delta-<abi>.patch` from a previous + new per-ABI APK and a machine-readable
  `delta-report.json` (`{ base, target, patch { bytes, kb }, ratio }`).
  Fails loudly when bsdiff fails or emits an empty patch — a broken delta must
  never ship; the summary prints the keep/skip hint (ratio ≤ 0.4 = worth it).
- **The shipped client behavior is the FALLBACK** (full verified APK via the
  O1-13 PackageInstaller flow) — no on-device bspatch/re-sign path exists
  until the CI-measured ratios justify one. That decision boundary is
  documented in docs/updates.md and enforced by the script's loud-failure
  posture: the stretch goal's "fallback to full APK" acceptance is the
  currently-shipped path, and the "measured sizes" come from the CI run.
- **CI request** (LEAD-applied, `docs/SHARED_CHANGES.md`): install bsdiff in
  the android matrix job, download the previous release's same-ABI APK, run
  the script, upload `dist/delta` with the release assets.
