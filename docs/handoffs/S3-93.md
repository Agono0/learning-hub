# S3-93 — Notes↔project linking (project notes)

**Status:** done. **Worker:** W2. **Commit:** `b2ffb19`.

## Design

No schema change: a note links to a task project through its typed-supertag
`fields` JSON — `fields.projectId = String(taskProject.id)` — which the
EXISTING notes PATCH (`fields: Record<string,string> | null`) already
maintains (`null` clears every field = unlink). The new surface is the READ
side:

- `listNotes({ projectId })` (`packages/db/src/repos/notes.ts`) filters via
  `json_extract(fields, '$.projectId') = ?` (string comparison — the fields
  values are strings), composable with the existing `query` text filter
  (conditions accumulate into one `where(and(...))`).
- `GET /api/notes?projectId=7` (`handlers/notes/route.ts`) passes the
  filter; a malformed value degrades to NO filter (the full list — honest
  fallback, tested).

## Tests

`tests/notes-project-linking.test.ts` (4, the settings-haptics temp-DB
pattern): project creation + linked/unlinked notes → the filter returns
only linked ones; query+filter combination; PATCH maintains the link and
`fields: null` clears it; the malformed-filter fallback. 4/4 green.
