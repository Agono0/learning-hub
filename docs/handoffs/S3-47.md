# S3-47 — Repeat-config dialog

**Status:** done. **Worker:** W2. **Commit:** `e1797c8`.

## Component

`apps/web/src/components/tasks/RepeatConfigDialog.tsx` — kit `Sheet`
(bottom sheet on phones / centered modal from md) over the repeat-cfgs
routes:

- **Fields:** optional rule name (persisted via migration 034's `title`),
  cycle (`d/w/m/y`), interval (1–999), start date (day-key, defaults to
  today), optional end date, re-anchor mode (`completion` / `scheduled` /
  `postponed` with plain-language copy), and skip dates (day-key chips,
  add/remove, sorted).
- **Validation** (`validateRepeatDraft`, exported): interval must be a whole
  number 1–999; start/end must be `YYYY-MM-DD`; end ≥ start; empty end =
  open-ended rule. Mirrors the handler boundary so the save button only
  enables on a body that will pass zod.
- **Persistence:** POST creates / PATCH edits `/api/tasks-repeat-cfgs`;
  `onSaved(cfg)` hands the row back so the parent links the task's
  `repeatCfgId`; the repeat-cfgs query invalidates on success. Server
  errors surface inline (`role="alert"`).
