# M2-16 — Pre-session checklist UI (and M2-32 tier checklist core)

**Status:** done (M2-16 + M2-32). **Branch:** `feature/mega-run`. **Worker:** W2.

## Component

`apps/web/src/components/MaxFocusPrecheck.tsx` — rendered in the focus page's
Max Focus configurator, directly above the start button:

1. **What will be blocked** — chips of the RESOLVED allowlist (defaults +
   selected preset + extras, normalized via core `normalizeDomain` /
   `normalizeExeName`) under the honest line "Only these stay reachable —
   every other site and desktop app is blocked". Empty selection shows a
   real note instead of an empty chip row.
2. **Permission audit** (M2-32's checklist rendered) — per-tier
   granted-vs-needed rows for the strongest tier this device can enforce:
   - Windows/Tauri desktop → `windows-basic` (keyboard hook inherent),
   - Android → Device Owner state from `deviceOwnerStatus()` (owner vs
     admin-only vs none),
   - Web → the extension bridge is the only shield; the audit says so
     instead of faking a tier.
   The audit runs in a mount effect; SSR renders "Checking what this device
   can enforce…" — never a guessed tier.
3. **Explicit confirm** — a `Toggle`: "I understand: this device stays locked
   until the timer ends or the 4-hour cap". The page's **Engage Max Focus
   button is disabled until it is checked** (state lives in the page:
   `precheckConfirmed`).

## Core (M2-32)

`packages/core/src/focus-lock/tiers.ts` (re-exported from the focus-lock
index):

- `TIER_REQUIREMENTS` — the per-tier permission matrix
  (owner/accessibility/windows-admin/windows-basic);
- `tierChecklist(tier, granted)` — rows + missing + satisfied
  (case/whitespace-insensitive, sharing `missingRequiredPermissions` with
  the M2-20 tamper check);
- `bestAvailableTier(granted)` — strongest fully-satisfied tier or null
  (the honest "cannot lock" answer);
- `TIER_PERMISSION_LABELS` — the UI's one-line copy per permission.
