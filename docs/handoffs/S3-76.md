# S3-76 — Recently-deleted trash view + device-local store

**Status:** done. **Worker:** W2. **Commit:** `24dae63`.

## Store

`apps/web/src/lib/task-trash.ts` — device-local (localStorage `lh:task-trash`,
200-entry cap): the DELETE /api/tasks/[id] handler returns the S3-12 trash
entry and the client stashes it here — device-local by design (the
snapshot-sync merge must never resurrect deleted rows on other devices, the
same reasoning as the sync roster). Reads purge expired rows lazily via the
core TTL math; every record round-trips through the FULL core
`trashEntrySchema` (so a stored `deletedAt` — the TTL anchor — survives,
never re-stamped; corrupted records degrade to fewer rows). Exports:
`listTrashEntries(now)`, `expiredTrashIds(now)`, `putTrashEntry`,
`removeTrashEntry`, `purgeExpiredEntries(now)`, `restoreFromTrash(taskId)`
(POST /api/tasks/[id]/restore then drop locally).

## View

`apps/web/src/components/tasks/TrashView.tsx` — newest-first rows with the
denormalized title, deletion day + via, a days-left badge (danger at the
purge edge, warning ≤3 days — `expiryTone`), per-row restore, and a "Purge N
expired" affordance when the read finds expired rows. Honest states: SSR
renders nothing until the client clock mounts (hydration-safe), loading
note after mount, `EmptyState` ("rest here for 30 days") when empty, inline
errors. Wiring: mount under the tasks page's archive/trash surface
(`onRestored` invalidates the task list).
