# M2-31 — "Session running" + unlock notifications

**Status:** done. **Branch:** `feature/mega-run`. **Worker:** W2.

## Channel (core)

`packages/core/src/notification-center/index.ts` — new catalog channel
`max_focus` (category `focus`, defaultEnabled + defaultViaOs `true`),
additively appended to `NOTIFICATION_CHANNEL_IDS`. Existing prefs merge
through `parseNotificationPrefs` defaults, so existing users get the channel
automatically; the generic per-channel tests in
`packages/core/tests/notification-center.test.ts` cover it by iteration.

## Watcher (web)

`apps/web/src/lib/use-max-focus-notifier.tsx` — `MaxFocusNotifier`, mounted
once in `apps/web/src/components/Providers.tsx`. It polls
`GET /api/focus/max` (same `['focus-max-lock']` key the focus page uses —
react-query dedupes) and fires on EDGES only
(`maxFocusNotificationDecision`, pure + exported):

- **inactive → active (engaged):** "Max Focus engaged — locked until HH:MM.
  Exits need your PIN and a written reason." Delivered with
  `tag: 'max-focus-session'` + web `requireInteraction`, so it is the one
  persistent "session running" toast and is later REPLACED (not stacked) by
  the unlock toast.
- **active → inactive (unlocked):** "Max Focus unlocked — the lock lifted.
  Focus Studio shows how the session ended." (The exact ending is narrated by
  the M2-34 report card; the copy stays honest without extra fetches.)

Every decision — delivered AND suppressed — is logged to
`/api/notifications/log` (same shape the global timer uses), and delivery
goes through `evaluateDelivery('max_focus', …)`, so quiet hours, DND, master
switch and the daily cap all apply.

## Platform seam

`apps/web/src/platform/permissions.ts` — `deliverLocalNotification` gained an
optional `LocalNotificationOptions` (`tag`, `requireInteraction`) applied on
web hosts; the Tauri plugin path ignores them.

## Tests

`apps/web/tests/max-focus-notifier.test.ts` — pure decision edges (no
