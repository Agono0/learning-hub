# S3-33 + S3-78 — Idle detection & classify dialog

**Status:** done (both). **Worker:** W2. **Commit:** `67236a4`.

## Core

`packages/core/src/tasks/idle.ts` — the SP gate over an idle gap:

- **jitter** (< `ignoreMs`, default 2 min) → `active`, never prompts;
- **break** (ignore→`discardMs`) → `suggest-break` (information only —
  nothing subtracted);
- **discard** (≥ `discardMs`, default 10 min) → `suggest-discard` with
  `subtractMs` CAPPED at the threshold (a forgotten-overnight gap cannot
  wipe the day's log);
- **Max Focus suppression** (S3-34's idle half): `maxFocusActive: true`
  returns `active` with `suppressedBy: 'max-focus'` — the gate never
  prompts against a lock. `applyIdleSubtraction` applies the dialog's
  action (`assign` keeps, `break` keeps, `discard` subtracts, floored at 0).

## Native

`apps/native/src-tauri/src/idle.rs` — `system_idle_ms` command: Windows
reads `GetLastInputInfo`/`GetTickCount` via self-contained extern bindings
(user32/kernel32 link automatically — NO Cargo feature or shared-file edit
needed; an OPTIONAL crate-feature upgrade is noted in
docs/SHARED_CHANGES.md). Non-Windows returns `available: false` (the
webview hides the gate). Registered in `lib.rs` (`mod idle;` +
`idle::system_idle_ms` in the invoke handler). Compile-verified in CI.

## UI

`apps/web/src/components/tasks/IdleClassifyDialog.tsx` — kit `Sheet` over
the verdict: "Keep tracking" (assign), "It was a break" (log nothing
extra), and "Discard N min of dead time" only when the verdict allows;
"Decide later" closes. Active/suppressed verdicts never open the dialog
(`shouldPrompt`). The page glue: poll `system_idle_ms` while a task is
tracked, classify on return, apply via `applyIdleSubtraction` — a small
follow-up for the timer owner (`use-global-timer`).
