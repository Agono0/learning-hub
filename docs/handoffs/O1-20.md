## What was built

- `Nightly OTA` gained a `measure_patch` dispatch input. When true, the release
  job is skipped entirely (`if: !inputs.measure_patch`) and the
  `measure-patch` job runs instead — a scheduled/normal dispatch is unaffected.
- The probe: `npm run web:tauri` (baseline) → snapshot manifest (version
  `00000000-base`) → append ONE comment line (`// nightly patch-size probe …`)
  to `apps/web/app/layout.tsx` → `npm run web:tauri` again →
  `update-manifest.mjs --prev base-manifest.json` → the emitted
  `patch-00000000-base-00000000-probe.zip` IS the hot patch a nightly would
  ship for a one-line edit.
- Reporting: prints `PASS: … = N KB (< 50 KB target)` or
  `DEVIATION: … exceeds the 50 KB target`, writes the number + bundle file
  count into `$GITHUB_STEP_SUMMARY` (copy into release notes), and errors
  clearly if the probe changed no export files.

## Acceptance status (honest)

The measured NUMBER cannot be produced locally (rule 17 — no local builds);
it lands in the run summary of the first `measure_patch=true` dispatch.
`docs/updates.md` §"Measured hot patch size" now contains the method, the
results table (to be filled from the first CI run) and the deviation policy —
i.e. the "explained" path of the acceptance is documented, and the table is
the single place to record CI numbers.

## Notes

- The probe job intentionally does not sign or publish anything.
- If a future probe exceeds 50 KB, likely cause is a shared chunk invalidated
  across builds — record the number in the table and the cause next to it.
