# M2-07 handoff — Task Manager/desktop-switch detect + refocus loop

Worker: W3 · Branch: `feature/mega-run` · Files: `apps/native/src-tauri/src/lock_win.rs`
(`refocus` module + pure decision fns + lifecycle wiring + tests). Dep: M2-06.

## What was built

- **Pure decision** `needs_refocus(foreground_process, foreground_is_lock_window)`:
  refocus when the foreground window is NOT a lock window, or when the
  foreground process is Task Manager — Ctrl+Alt+Del cannot be hooked at any
  tier (documented limit, docs/LIMITATIONS.md O1-24), so tier 1's answer is to
  steal focus straight back. `file_name_tail` normalizes image paths from both
  separators (test matrix included).
- **`refocus` module** (cfg(windows)): a 500 ms polling loop
  (`POLL_INTERVAL_MS` — one GetForegroundWindow + PID lookup per tick, hours-cheap)
  started by `apply_lock_windows` and stopped by `release_lock_windows`
  (idempotent, session-scoped like the M2-06 hook). Each tick:
  1. Collect lock-window HWNDs (`WebviewWindow::hwnd()` — tauri 2.12.5 IS
     windows-0.62, the exact same HWND type; verified in the registry sources).
  2. Get the foreground window's process image name
     (`OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION)` +
     `QueryFullProcessImageNameW`, CloseHandle always).
  3. When `needs_refocus` fires: `SetWindowPos(HWND_TOPMOST)` +
     `SetForegroundWindow` on the first lock window — best-effort focus steal
     (the OS may refuse without foreground rights; the TOPMOST z-order still
     wins visually, and M2-08's admin tier hardens this).
  4. Task Manager detections log for the session friction trail (M2-20/M2-21
     can correlate).
- No new Cargo features: PROCESS_QUERY_LIMITED_INFORMATION/QueryFullProcessImageNameW
  live in the already-enabled Win32_System_Threading + ProcessStatus is unused
  here; everything else is Win32_UI_WindowsAndMessaging (already enabled).
