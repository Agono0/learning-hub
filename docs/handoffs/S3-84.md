# S3-84 — Eisenhower keyboard quadrant nav (+ S3-100 boards a11y sweep)

`apps/web/app/boards/page.tsx` (one commit covers both — same surface).

## S3-84 keyboard nav

Full keyboard alternative to dragging on the Eisenhower grid (2×2, columns
ordered q1 q2 / q3 q4):

- Arrow keys walk the grid (left/right flip the low bit, up/down ±2; clamped
  at the edges); the focused quadrant gets an indigo border + the global
  focus-visible ring.
- `X` / `Enter` picks up the FIRST task of the focused quadrant (`held`);
  with a task held, arrows move and `Enter` drops it (applies the quadrant's
  chip through the same `applyMove` path as a drag — one rule engine); a
  held card dims; `Escape` cancels.
- An `aria-live="polite"` region narrates pick/drop state and the key map,
  so screen readers get the same flow.

## S3-100 a11y sweep (boards side)

- Quadrants are focusable (`tabIndex={0}`, `role`-labeled via aria-label
  with the live task count + "focused" state) and carry the kit-standard
  `focus-visible:ring-(--ac-strong)` ring (no banned ring classes).
- Cards: `role="list"` / `role="listitem"` semantics, focusable draggable
  wrappers with honest aria-labels ("drag to a column, or use the Move
  select below"), grip icon `aria-hidden`.
- The per-column "Move a task here…" select remains the pointer-free path
  on every board kind (kanban/custom included) — keyboard users never NEED
  drag. Planner-side a11y belongs to W1's S3-25 surface; noted here so the
  sweep's other half is not assumed done.
