# S3-28 — Worklog page: day/week history, inline corrections, CSV export

`apps/web/app/worklog/page.tsx` (+ `apps/web/tests/worklog-page.test.ts`).

Consumes W1's landed S3-18 surface through the hub transport (rule 1):

- `GET /api/tasks-worklog?from&to` — `{ from, to, totalMs, perDay[{day,
  totalMs}], perTask[{taskId,title,totalMs}], logCount }` for the rollups.
- `GET /api/tasks-time?from&to` — `{ logs[], totalMs }` session rows (the
  correction targets; titles are joined from the rollup's perTask map).
- `DELETE /api/tasks-time/[id]` — an inline correction: two-tap confirm
  (Delete → Confirm delete / Keep), then the task's per-day map is
  re-derived server-side (SP semantics — never hand-patched).
- `GET /api/tasks-worklog/export?from&to` — CSV through `apiDownload`
  (native shells get the save dialog).

UI: Today/This-week tabs (Tabs kit), total + session-count summary, honest
per-day bars (static widths — no transition on width, motion law) and a
per-task list, the sessions list with per-row corrections, honest empty
state ("No tracked time yet"). SSR-safe: ranges + data are client-only
(effect-set `from`/`to`), so `renderToString` (pending-fetch stub in the
test) matches hydration — the test also asserts no `Date.toISOString` at
render time.

`formatMs` is exported for tests (calm `45m` / `1h 24m` numerals).

Contract pinning: `WorklogRollup` / `SessionLog` types are exported from
the page; the test pins the JSON shapes both sides share, so drift between
this page and the S3-18 handlers breaks in CI, not at runtime. If W1's
final S3-18 commit renames fields, that test names the fix.

S3-88 (core worklog week/month rollups + leaf-only totals) can upgrade the
rollup MATH later without touching this page — the response shape stays.
