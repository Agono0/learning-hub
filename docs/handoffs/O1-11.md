## Pointer hosting model (the contract promote + nightly share)

One fixed GitHub release with tag **`channel-pointers`** holds the mutable
pointer assets — the stable URLs clients poll (GitHub's `releases/latest`
ignores prereleases, so a fixed release is required):

```
https://github.com/<owner>/<repo>/releases/download/channel-pointers/nightly.json
https://github.com/<owner>/<repo>/releases/download/channel-pointers/beta.json
https://github.com/<owner>/<repo>/releases/download/channel-pointers/stable.json
https://github.com/<owner>/<repo>/releases/download/channel-pointers/manifest-nightly.json (+ .sig)
https://github.com/<owner>/<repo>/releases/download/channel-pointers/manifest-beta.json   (+ .sig)
https://github.com/<owner>/<repo>/releases/download/channel-pointers/manifest-stable.json (+ .sig)
```

Every pointer matches `updatePointerSchema` (O1-01): `{ channel, version,
manifestUrl (https), publishedAt, notes }`. The nightly workflow (O1-08) got one
new step ("Publish nightly pointer to the channel-pointers release") that copies
`nightly.json` + `manifest-nightly.json` (+ sig — byte-identical to the release
manifest's sig) there on every nightly.

## What promote.yml does (manual dispatch only)

Inputs: `source_tag` (e.g. `nightly-20261122-abc1234`), `channel` (choice
beta|stable), optional `notes`. Single ubuntu job:

1. Validates the source release exists and carries a `manifest.json`.
2. Downloads its `manifest.json` + `nightly.json` (version + notes source).
3. Rewrites the manifest copy with `channel: <target>` → `manifest-<target>.json`
   and writes `<target>.json` pointer with `manifestUrl` pointing at the
   channel-pointers copy (patches/installer URLs still reference the source
   release — **artifacts are kept, never rebuilt or moved**).
4. Re-signs both with the minisign key (`tauri signer sign`): the manifest bytes
   changed (channel field), so the old signature is invalid; client verification
   is never disabled. Missing key secret ⇒ `::warning::` + inert unsigned pointer.
5. Creates `channel-pointers` release if absent, deletes stale same-name assets,
   uploads the four files.
6. Prints a summary (version promoted, pointer URL).

Rollback = re-run pointing at an older build's tag; only the pointer moves
(on-device rollback is O1-05's boot-confirm, orthogonal).
