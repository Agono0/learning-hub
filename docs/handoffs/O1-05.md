# O1-05 — Boot-confirm rollback

update.rs: `MAX_BOOT_MISSES = 3`, `missed_confirmations` on the pointer
(backward-compatible with O1-03 pointers — tested), `boot_reconcile()`
(increments per boot; at the cap flips the pointer BACK to the other slot —
which holds the previously confirmed build — resets the counter, logs via the
existing `log` crate, and leaves the broken slot as the next download target),
`confirm_boot_ready()` (resets on webview-ready; no-op when already 0).
lib.rs: single platform-independent `setup` now boot-reconciles before the
webview loads (desktop tray moved verbatim into `setup_desktop_shell`),
plus the `update_confirm_boot_ready` command. Tests: increment→rollback,
confirm-reset idempotency, promoted-never-confirmed rollback, old-pointer
parse upgrade. COORDINATION: W2 (O1-12/O1-14) must invoke
`update_confirm_boot_ready` once from the client service after mount —
without it, every boot counts as missed and the app rolls back to bundled.
