# M2-18 — Early-exit flow UI (MaxFocusExitGate)

**Status:** done. **Branch:** `feature/mega-run`. **Worker:** W2.

## Component

`apps/web/src/components/MaxFocusExitGate.tsx` — one component owning the
whole early-exit arc, driven by the lock's `exitState` from
`GET /api/focus/max`:

| exitState | What renders |
| --- | --- |
| `locked` | the single "Request early exit — starts a 60-second reflection" affordance |
| `cooldown` | reflection timer (`{cooldownRemainingSec}s remaining`) + "Resist impulse and return to focus" (cancel POST logs the resistance win) |
| `can_confirm` (no vault) | first-use PIN setup — 4–12 digits + repeat, hashed client-side with core `createPinVault` (PBKDF2) and stored under `localStorage['lh:max-focus-pin-vault']` (device-local, M2-02 contract) |
| `can_confirm` (vault) | mandatory reason (≥ 20 chars, the zod boundary enforces it again) + PIN entry → `POST /api/focus/max/exit` with `{ action: 'confirm', reflection, pin, vault }` |
| `none` / `ended` / no lock | renders nothing |

Error handling: server errors (401 wrong PIN, 429 rate limit, 409 cooldown)
surface in a `Callout` inside the gate — never a toast-only failure.

## Page wiring

`apps/web/app/focus/page.tsx` — the three inline exit mutations and their
render blocks are REPLACED by `<MaxFocusExitGate lock={activeLock}
onChanged={exitGateChanged} onExited={exitGateExited} />`:

- `onChanged` → refetch `['focus-max-lock']` + focus history;
- `onExited` → releases the mobile focus presentation and, on Tauri desktop,
  invokes `focus_lock_release` (the glue the old confirm mutation owned —
  now only fires on a CONFIRMED exit).

The old inline flow POSTed confirm without a PIN and would have been rejected
by the M2-04 handler; this wiring is what makes the two compose.

## Tests

`apps/web/tests/max-focus-exit-gate.test.ts` — SSR renderToString of all
gate states (null-lock empty render, request, cooldown countdown, honest
"Checking PIN setup…" placeholder on the server), plus the pinned vault key
`lh:max-focus-pin-vault` and soft-fail vault reads without a window.

## Design-law notes

Kit-first (`Button`, `TextArea`, `TextField`, `Callout` from `@/ui`),
`--danger-text`/`--status-warning-text` tokens, no ghost vocabulary, no raw
fetch (transport only), motion-free (state text is the feedback —
confirm-in-place).
