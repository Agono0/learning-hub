## Bridging decisions (schema gaps — core model vs applied 031/032 tables)

Shared files are LEAD-only, so the repo bridges instead of migrating:

1. **Relative reminders have no `offset_ms` column.** `task_reminders
.remind_at` is NOT NULL and stores the offset in milliseconds as a
   string for `type='relative'` rows (e.g. `-1800000`). `reminderFromRow`
   is the only decode point. **REQUEST (docs/SHARED_CHANGES.md):** a future
   migration adding a nullable `offset_ms INTEGER` column to
   `task_reminders`; the repo would then switch decode in one place.
2. **`task_repeat_cfgs` has no `title` column** (core `RepeatCfg.title` is
   UI-side). The repo drops `title` on write. REQUEST: optional future
   `title TEXT` column; low priority (SP titles are generated).
3. SQLite FKs are off (031 note), so **repos own referential integrity**:
   parent/project/tag/repeat-cfg existence checks before writes; deletes
   cascade to dependent rows (verified by tests).
