## What was added

`parseUpdatePointer(raw: unknown): UpdatePointer | null` — the client-boundary
wrapper around `updatePointerSchema.safeParse`. Graceful on both axes:

- **Unknown fields are stripped** (zod object default), so a future pointer
  format (e.g. a `rolloutPercent` field) still validates against old clients —
  pointer evolution can never brick the updater.
- **Invalid input returns `null`, never throws** — callers treat `null` as
  "no update information this cycle" (log + retry next interval). `null`,
  `undefined`, strings, numbers and arrays are all handled.

## Test list (in packages/core/tests/update.test.ts)

- pointer schema strips unknown fields and parses to exactly the known shape.
- `parseUpdatePointer`: valid pointer parses (RFC 3339 with numeric offset
  accepted); unknown fields stripped; returns `null` (no throw) for http
  manifestUrl / unknown channel / empty version / null / undefined / string /
  number / array inputs; JSON round-trip as the client fetches it.
